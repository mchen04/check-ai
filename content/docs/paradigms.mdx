# Verification Methods

Check uses a multi-paradigm approach to verification, combining seven distinct methods to determine the truthfulness of claims. Each method has different strengths, False Positive Rates (FPR), and use cases.

## Overview

| Method | FPR | Speed | Best For |
|--------|-----|-------|----------|
| [Semantic](#semantic) | ~20-30% | Fast | Quick sanity checks |
| [Reasoning](#reasoning) | ~4-5% | Medium | General fact verification |
| [Tool](#tool) | ~1% | Slow | Real-time fact-checking |
| [BIPRM](#biprm) | ~5-7% | Medium | Complex reasoning chains |
| [Ensemble](#ensemble) | ~15-20% | Slow | High-stakes decisions |
| [Entropy](#entropy) | ~8-10% | Medium | Consistency validation |
| [Formal](#formal) | 0% | Fast | Mathematical claims |

**FPR (False Positive Rate)** = Probability of incorrectly verifying a false claim as true. Lower is better.

## Method Details

### Semantic

Boltzmann energy-based embedding analysis with batch cached references for efficient similarity verification.

| Property | Value |
|----------|-------|
| FPR | ~20-30% |
| Speed | Fast (~100ms) |
| Cost | Low |

**How it works:**
1. Converts the claim to a vector embedding
2. Computes Boltzmann energy distributions over embeddings against batch cached reference facts (single API call)
3. Returns energy-based confidence score (lower energy = higher similarity)

**Best for:**
- Quick sanity checks
- Filtering obviously false claims
- High-volume, low-stakes verification

**Limitations:**
- Still the highest FPR method
- Cannot verify novel claims
- Struggles with nuanced statements

```typescript
const result = await client.verifyAndWait({
  content: 'Paris is the capital of France.',
  methods: { semantic: 1.0 }
});
```

### Reasoning

Adaptive self-refinement verification with conditional self-critique (test-time training) when confidence falls in the [0.4, 0.85] range.

| Property | Value |
|----------|-------|
| FPR | ~4-5% |
| Speed | Medium (~1-2s) |
| Cost | Medium |

**How it works:**
1. Sends the claim to an LLM with a verification prompt
2. If initial confidence is in [0.4, 0.85], triggers conditional self-critique (TTT) for refinement
3. Self-critique challenges the initial reasoning and produces a refined verdict

**Best for:**
- General fact verification
- Claims requiring contextual understanding
- Balance of speed and accuracy

**Limitations:**
- Relies on LLM's training data
- May not have recent information
- Self-critique adds latency for borderline cases

```typescript
const result = await client.verifyAndWait({
  content: 'The Great Wall of China is visible from space.',
  methods: { reasoning: 1.0 }
});
```

---

### Tool

CLoVE (Contrastive Language-grounded Verification) with per-source independence scoring and contrastive reasoning.

| Property | Value |
|----------|-------|
| FPR | ~1% |
| Speed | Slow (~2-5s) |
| Cost | High |

**How it works:**
1. Extracts key claims using CLoVE structured prompts
2. Searches authoritative sources with per-source independence scoring
3. Applies contrastive reasoning to weigh supporting vs. contradicting evidence
4. Returns verdict with source citations and independence-weighted confidence

**Best for:**
- Fact-checking current events
- Verifying statistics and numbers
- Claims about real-world entities

**Limitations:**
- Slower due to web requests
- Depends on source availability
- Higher cost per verification

```typescript
const result = await client.verifyAndWait({
  content: 'The population of Tokyo is over 14 million.',
  methods: { tool: 1.0 }
});

// Returns sources in paradigmResults
console.log(result.paradigmResults[0].sources);
// ['https://en.wikipedia.org/wiki/Tokyo', ...]
```

### BIPRM

Parallel bidirectional (L2R/R2L) step-level scoring via Promise.all() for debiased reasoning from multiple angles.

| Property | Value |
|----------|-------|
| FPR | ~5-7% |
| Speed | Medium (~1-3s) |
| Cost | Medium-High |

**How it works:**
1. Runs left-to-right (L2R) and right-to-left (R2L) reasoning in parallel via Promise.all()
2. Scores each reasoning step independently for step-level granularity
3. Aggregates bidirectional step scores to produce a debiased verdict
4. BiPRM x Formal synergy: when both methods run, orchestrator cross-validates results

**Best for:**
- Controversial or debatable claims
- Claims with multiple interpretations
- Content requiring nuanced analysis

**Limitations:**
- May be indecisive on clear-cut claims
- Higher cost than single-pass reasoning
- Can be slower for simple claims

```typescript
const result = await client.verifyAndWait({
  content: 'Electric vehicles are better for the environment than gas cars.',
  methods: { biprm: 1.0 }
});
```

---

### Ensemble

Meta-judge adjudicated multi-model consensus with conditional meta-judge activation when members disagree.

| Property | Value |
|----------|-------|
| FPR | ~15-20% |
| Speed | Slow (~3-5s) |
| Cost | High |

**How it works:**
1. Sends claim to multiple LLM providers (GPT-4, Claude, Gemini, etc.)
2. Collects verdicts from each model
3. When members disagree, a conditional meta-judge adjudicates the dispute
4. Returns consensus verdict with confidence

**Best for:**
- High-stakes decisions requiring agreement
- Reducing single-model bias
- Important content where accuracy is critical

**Limitations:**
- Highest cost (multiple API calls)
- Slowest method
- Can still have correlated errors

```typescript
const result = await client.verifyAndWait({
  content: 'This medication is safe for children under 12.',
  methods: { ensemble: 1.0 }
});
```

---

### Entropy

Dual-path semantic entropy: logprobs fast path when available, behavioral path with semantic clustering as fallback.

| Property | Value |
|----------|-------|
| FPR | ~8-10% |
| Speed | Medium (~2-3s) |
| Cost | Medium |

**How it works:**
1. **Logprobs fast path**: When the model provides token-level log probabilities, computes entropy directly from logprobs for instant confidence estimation
2. **Behavioral path** (fallback): Generates multiple rephrasings, verifies each independently, then clusters responses using semantic similarity
3. Low entropy = high confidence, high entropy = uncertainty

**Best for:**
- Detecting hallucinations
- Checking reasoning consistency
- Claims that might be phrasing-dependent

**Limitations:**
- Can give false confidence on consistently wrong claims
- Behavioral path adds latency for rephrasings
- Logprobs path depends on provider support

```typescript
const result = await client.verifyAndWait({
  content: 'The CEO of Apple in 2023 was Tim Cook.',
  methods: { entropy: 1.0 }
});
```

---

### Formal

mathjs autoformalization with expanded claim classification for symbolic verification of mathematical claims.

| Property | Value |
|----------|-------|
| FPR | 0% |
| Speed | Fast (~100-500ms) |
| Cost | Low |

**How it works:**
1. Classifies claims into types: arithmetic, algebraic, comparison, statistical, unit conversion
2. Autoformalizes the claim into a mathjs expression using LLM-assisted translation
3. Evaluates the expression symbolically with mathjs for 0% FPR (mathematical certainty)
4. Claims outside supported categories fall back to LLM-based reasoning (~5-7% FPR)

**Best for:**
- Arithmetic calculations
- Algebraic identities
- Numerical comparisons
- Statistical claims
- Unit conversions

**Limitations:**
- Only works for formalizable claims within supported categories
- Cannot verify subjective statements
- Full theorem prover integration (Lean, Coq, Z3) is planned

```typescript
// Arithmetic verification
const result = await client.verifyAndWait({
  content: 'The square root of 144 is 12.',
  methods: { formal: 1.0 }
});

// Logical verification
const result = await client.verifyAndWait({
  content: 'If A implies B and B implies C, then A implies C.',
  methods: { formal: 1.0 }
});
```

## Combining Methods

Methods can be combined with weights to balance accuracy and speed:

### Fast + Reasonably Accurate (Chatbots)

```typescript
const result = await client.verifyAndWait({
  content: 'Your claim here',
  methods: { reasoning: 1.0 }
});
```
- ~1-2 second response
- ~4-5% FPR
- Good for real-time applications

### High Accuracy (Important Content)

```typescript
const result = await client.verifyAndWait({
  content: 'Critical claim requiring verification',
  methods: {
    reasoning: 1.0,
    tool: 1.0,
    biprm: 0.5
  }
});
```
- 3-5 second response
- ~2-5% FPR
- Good for healthcare, legal, financial

### Maximum Confidence (Critical Decisions)

```typescript
const result = await client.verifyAndWait({
  content: 'Claim with major consequences if wrong',
  methods: {
    reasoning: 1.0,
    tool: 1.0,
    ensemble: 1.0,
    biprm: 0.5
  }
});
```
- 5-10 second response
- ~1-2% FPR
- Good for publication, legal documents

### Mathematical Claims

```typescript
const result = await client.verifyAndWait({
  content: '2^10 = 1024',
  methods: { formal: 1.0 }
});
```
- ~100ms response
- 0% FPR
- Perfect for calculations

## How Results Are Aggregated

Check uses FPR-weighted voting to combine results from multiple methods:

1. **Each method returns:**
   - Verdict: `true`, `false`, or `uncertain`
   - Confidence: 0.0 to 1.0

2. **Weights are calculated based on:**
   - Method's FPR (lower FPR = higher weight)
   - User-specified method weight
   - Method's confidence in its verdict

3. **Final verdict is determined by:**
   - Weighted vote across all methods
   - If methods strongly disagree, verdict becomes `uncertain`

4. **Decision thresholds:**
   | Confidence | Decision | Condition |
   |------------|----------|-----------|
   | >= 0.95 | `accept` | High confidence |
   | 0.70 – 0.95 | `refine` | Moderate confidence |
   | < 0.70 | `escalate` | Low confidence + paradigm disagreement |
   | < 0.70 | `reject` | Low confidence + paradigm agreement |

## Choosing Methods by Use Case

### Real-Time Applications

**Chatbots, live responses:**
```typescript
methods: { reasoning: 1.0 }
```

### Content Moderation

**Social media, user-generated content:**
```typescript
methods: { reasoning: 1.0, tool: 0.5 }
```

### Healthcare

**Medical information verification:**
```typescript
methods: { reasoning: 1.0, tool: 1.0, ensemble: 1.0 }
```

### Finance

**Financial claims and data:**
```typescript
methods: { reasoning: 1.0, tool: 1.0, formal: 0.5 }
```

### Legal

**Legal documents and claims:**
```typescript
methods: { reasoning: 1.0, tool: 1.0, biprm: 1.0 }
```

### Education

**Textbook content verification:**
```typescript
methods: { reasoning: 1.0, tool: 1.0 }
```

### Scientific

**Research claims:**
```typescript
methods: { reasoning: 1.0, tool: 1.0, formal: 0.5, entropy: 0.5 }
```

## Cost Optimization

Methods have different costs. Optimize by:

1. **Start with reasoning** - Best balance of cost/accuracy
2. **Add tool for factual claims** - When current info needed
3. **Use ensemble sparingly** - Only for critical decisions
4. **Use formal for math** - Cheapest and most accurate for calculations

```typescript
// Cost-effective pipeline
async function verify(content: string, importance: 'low' | 'medium' | 'high') {
  const methods = {
    low: { reasoning: 1.0 },
    medium: { reasoning: 1.0, tool: 0.5 },
    high: { reasoning: 1.0, tool: 1.0, ensemble: 0.5 }
  };

  return client.verifyAndWait({
    content,
    methods: methods[importance]
  });
}
```
