# Environment Variables

This guide covers all environment variables needed to run Check in development and production.

## Quick Setup

Copy the example file and fill in your values:

```bash
cp .env.example .env.local
```

## Required Variables

These environment variables are required for Check to function:

### Supabase (Authentication & Database)

| Variable | Description | Example |
|----------|-------------|---------|
| `NEXT_PUBLIC_SUPABASE_URL` | Your Supabase project URL | `https://xxxxx.supabase.co` |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anonymous (public) key | `eyJhbGciOiJIUzI1NiIs...` |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service role key (server-side only) | `eyJhbGciOiJIUzI1NiIs...` |

**Where to find:**
1. Go to [Supabase Dashboard](https://app.supabase.io)
2. Select your project
3. Settings → API
4. Copy the URL, `anon` key, and `service_role` key

<Callout type="warning">
Never expose `SUPABASE_SERVICE_ROLE_KEY` to the client. It bypasses Row Level Security.
</Callout>

### Database

| Variable | Description | Example |
|----------|-------------|---------|
| `DATABASE_URL` | PostgreSQL connection string | `postgresql://user:pass@host:5432/db?sslmode=require` |

You can use:
- Supabase's built-in PostgreSQL
- Vercel Postgres
- Neon
- PlanetScale (with adapter)
- Any PostgreSQL provider

### Stripe (Payments)

| Variable | Description | Example |
|----------|-------------|---------|
| `STRIPE_SECRET_KEY` | Stripe secret API key | `sk_live_...` or `sk_test_...` |
| `STRIPE_WEBHOOK_SECRET` | Webhook signing secret | `whsec_...` |
| `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | Stripe publishable key | `pk_live_...` or `pk_test_...` |
| `NEXT_PUBLIC_STRIPE_PRICING_TABLE_ID` | Pricing table ID | `prctbl_...` |

**Where to find:**
1. Go to [Stripe Dashboard](https://dashboard.stripe.com)
2. Developers → API keys
3. For webhook secret: Developers → Webhooks → Select endpoint → Signing secret

### Website URL

| Variable | Description | Example |
|----------|-------------|---------|
| `NEXT_PUBLIC_WEBSITE_URL` | Your application URL | `http://localhost:3000` or `https://check.ai` |

Used for:
- OAuth redirects
- Webhook URLs
- Email links

## Optional Variables

### Upstash Redis (Rate Limiting & Caching)

| Variable | Description | Example |
|----------|-------------|---------|
| `UPSTASH_REDIS_REST_URL` | Upstash REST API URL | `https://xxx.upstash.io` |
| `UPSTASH_REDIS_REST_TOKEN` | Upstash REST API token | `AXxxxx...` |

**Where to find:**
1. Go to [Upstash Console](https://console.upstash.com)
2. Create or select a Redis database
3. REST API section

If not configured, rate limiting falls back to in-memory (not suitable for production).

### Trigger.dev (Background Jobs)

| Variable | Description | Example |
|----------|-------------|---------|
| `TRIGGER_SECRET_KEY` | Trigger.dev secret key | `tr_dev_...` |

**Where to find:**
1. Go to [Trigger.dev Dashboard](https://cloud.trigger.dev)
2. Select your project
3. Settings → API Keys

### Resend (Email)

| Variable | Description | Example |
|----------|-------------|---------|
| `RESEND_API_KEY` | Resend API key | `re_...` |
| `RESEND_FROM_EMAIL` | Sender email address | `noreply@check.ai` |

**Where to find:**
1. Go to [Resend Dashboard](https://resend.com)
2. API Keys section

### LLM Provider Keys

Platform-level API keys for LLM providers. Users can also bring their own keys (BYOK).

| Variable | Description |
|----------|-------------|
| `OPENAI_API_KEY` | OpenAI API key |
| `ANTHROPIC_API_KEY` | Anthropic API key |
| `GOOGLE_AI_API_KEY` | Google AI (Gemini) API key |
| `DEEPSEEK_API_KEY` | DeepSeek API key |
| `GROQ_API_KEY` | Groq API key |
| `TOGETHER_API_KEY` | Together AI API key |
| `MISTRAL_API_KEY` | Mistral API key |
| `COHERE_API_KEY` | Cohere API key |

At least one LLM provider key is recommended for the platform to function without BYOK.

### OAuth Providers

For social login support:

| Variable | Description |
|----------|-------------|
| `GOOGLE_OAUTH_CLIENT_ID` | Google OAuth client ID |
| `GOOGLE_OAUTH_CLIENT_SECRET` | Google OAuth client secret |
| `GITHUB_OAUTH_CLIENT_ID` | GitHub OAuth client ID |
| `GITHUB_OAUTH_CLIENT_SECRET` | GitHub OAuth client secret |

**Setup guides:**
- [Google OAuth](https://supabase.com/docs/guides/auth/social-login/auth-google)
- [GitHub OAuth](https://supabase.com/docs/guides/auth/social-login/auth-github)

### Encryption

| Variable | Description | Example |
|----------|-------------|---------|
| `ENCRYPTION_KEY` | 32-byte hex key for BYOK encryption | `0123456789abcdef...` (64 chars) |

Generate a secure key:

```bash
openssl rand -hex 32
```

If not set, a default development key is used. **Always set this in production.**

## Environment-Specific Configuration

### Development (.env.local)

```bash
# Supabase
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIs...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIs...

# Database
DATABASE_URL=postgresql://postgres:password@localhost:5432/check

# Stripe (Test Mode)
STRIPE_SECRET_KEY=sk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...

# Website
NEXT_PUBLIC_WEBSITE_URL=http://localhost:3000

# LLM (at least one)
OPENAI_API_KEY=sk-...

# Optional for development
UPSTASH_REDIS_REST_URL=
UPSTASH_REDIS_REST_TOKEN=
RESEND_API_KEY=
```

### Production (.env)

```bash
# Supabase (Production project)
NEXT_PUBLIC_SUPABASE_URL=https://xxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIs...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIs...

# Database (Production)
DATABASE_URL=postgresql://user:pass@host:5432/check?sslmode=require

# Stripe (Live Mode)
STRIPE_SECRET_KEY=sk_live_...
STRIPE_WEBHOOK_SECRET=whsec_...
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_live_...
NEXT_PUBLIC_STRIPE_PRICING_TABLE_ID=prctbl_...

# Website
NEXT_PUBLIC_WEBSITE_URL=https://check.ai

# Redis (Required for production)
UPSTASH_REDIS_REST_URL=https://xxx.upstash.io
UPSTASH_REDIS_REST_TOKEN=AXxxxx...

# Background Jobs
TRIGGER_SECRET_KEY=tr_prod_...

# Email
RESEND_API_KEY=re_...
RESEND_FROM_EMAIL=noreply@check.ai

# Encryption (Required for production)
ENCRYPTION_KEY=your-32-byte-hex-key

# LLM Providers
OPENAI_API_KEY=sk-...
ANTHROPIC_API_KEY=sk-ant-...
```

## Vercel Deployment

When deploying to Vercel:

1. Go to Project Settings → Environment Variables
2. Add each variable
3. Select environments (Production, Preview, Development)

<Callout type="info">
Variables prefixed with `NEXT_PUBLIC_` are exposed to the browser. Never put secrets in these variables.
</Callout>

## Security Best Practices

### Do

- Use different keys for development and production
- Rotate keys periodically
- Use a secrets manager for production (Vercel, AWS Secrets Manager, etc.)
- Keep `.env.local` in `.gitignore`

### Don't

- Commit `.env` files to version control
- Share keys via chat or email
- Use production keys in development
- Expose server-side keys to the client

## Troubleshooting

### "Invalid API key" Errors

1. Check that the key is set correctly (no extra spaces)
2. Verify the key hasn't been revoked
3. Ensure you're using the right environment (test vs live)

### "Missing environment variable" Warnings

1. Check that all required variables are set
2. Restart your development server after adding variables
3. Clear `.next` cache: `rm -rf .next`

### Database Connection Issues

1. Verify `DATABASE_URL` format is correct
2. Check that SSL mode matches your provider's requirements
3. Ensure your IP is whitelisted (if applicable)

### Stripe Webhooks Not Working

1. Verify `STRIPE_WEBHOOK_SECRET` matches your endpoint
2. For local development, use Stripe CLI: `stripe listen --forward-to localhost:3000/api/webhooks/stripe`
3. Check webhook logs in Stripe Dashboard
