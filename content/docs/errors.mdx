# Error Handling

The Verifact API uses conventional HTTP status codes and returns detailed error information to help you handle issues gracefully.

## Error Response Format

All errors return a consistent JSON structure:

```json
{
  "error": {
    "code": "error_code",
    "message": "Human-readable error message",
    "details": [
      {
        "field": "content",
        "message": "Field-specific error message"
      }
    ]
  }
}
```

### Error Fields

| Field | Description |
|-------|-------------|
| `code` | Machine-readable error code |
| `message` | Human-readable description |
| `details` | Array of field-specific errors (for validation errors) |

## HTTP Status Codes

### Client Errors (4xx)

| Status | Code | Description |
|--------|------|-------------|
| 400 | `bad_request` | Invalid request format or parameters |
| 401 | `unauthorized` | Missing or invalid API key |
| 403 | `forbidden` | Valid key but insufficient permissions |
| 404 | `not_found` | Resource doesn't exist |
| 409 | `conflict` | Resource already exists or state conflict |
| 422 | `validation_error` | Request validation failed |
| 429 | `rate_limited` | Too many requests |

### Server Errors (5xx)

| Status | Code | Description |
|--------|------|-------------|
| 500 | `internal_error` | Unexpected server error |
| 502 | `bad_gateway` | Upstream service error |
| 503 | `service_unavailable` | Temporary maintenance |

## Common Error Codes

### Authentication Errors

**401 - Missing API Key**
```json
{
  "error": {
    "code": "unauthorized",
    "message": "API key is required"
  }
}
```

**401 - Invalid API Key**
```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid API key"
  }
}
```

### Validation Errors

**400 - Missing Required Field**
```json
{
  "error": {
    "code": "validation_error",
    "message": "Validation failed",
    "details": [
      {
        "field": "content",
        "message": "Content is required"
      }
    ]
  }
}
```

**400 - Invalid Field Value**
```json
{
  "error": {
    "code": "validation_error",
    "message": "Validation failed",
    "details": [
      {
        "field": "mode",
        "message": "Must be 'fast' or 'standard'"
      }
    ]
  }
}
```

### Rate Limiting

**429 - Rate Limited**
```json
{
  "error": {
    "code": "rate_limited",
    "message": "Rate limit exceeded. Try again in 60 seconds.",
    "retryAfter": 60
  }
}
```

### Usage Limits

**403 - Monthly Limit Reached**
```json
{
  "error": {
    "code": "usage_limit_exceeded",
    "message": "Monthly verification limit reached. Upgrade your plan for more verifications.",
    "limit": 1000,
    "used": 1000
  }
}
```

## Handling Errors

### JavaScript/TypeScript

```typescript
async function verifyContent(content: string) {
  const response = await fetch('https://api.verifact.ai/v1/verify', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${apiKey}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ content }),
  });

  if (!response.ok) {
    const error = await response.json();

    switch (response.status) {
      case 401:
        throw new Error('Invalid API key');
      case 429:
        // Wait and retry
        const retryAfter = error.error.retryAfter || 60;
        await sleep(retryAfter * 1000);
        return verifyContent(content);
      case 400:
        throw new Error(`Validation error: ${error.error.message}`);
      default:
        throw new Error(`API error: ${error.error.message}`);
    }
  }

  return response.json();
}
```

### Python

```python
import time
import requests

def verify_content(content: str, max_retries: int = 3):
    for attempt in range(max_retries):
        response = requests.post(
            'https://api.verifact.ai/v1/verify',
            headers={'Authorization': f'Bearer {api_key}'},
            json={'content': content}
        )

        if response.ok:
            return response.json()

        error = response.json().get('error', {})

        if response.status_code == 429:
            retry_after = error.get('retryAfter', 60)
            time.sleep(retry_after)
            continue
        elif response.status_code == 401:
            raise AuthenticationError('Invalid API key')
        elif response.status_code >= 500:
            # Retry server errors
            time.sleep(2 ** attempt)
            continue
        else:
            raise APIError(error.get('message', 'Unknown error'))

    raise MaxRetriesExceeded()
```

## Best Practices

<Callout type="info" title="Retry Strategy">
For transient errors (429, 5xx), implement exponential backoff with jitter to avoid thundering herd problems.
</Callout>

### Implement Retries

Retry these status codes with exponential backoff:
- `429` - Rate limited (use `retryAfter` header)
- `500` - Internal server error
- `502` - Bad gateway
- `503` - Service unavailable

### Don't Retry These

- `400` - Fix the request
- `401` - Check your API key
- `403` - Check your permissions/plan
- `404` - Resource doesn't exist

### Log Errors

Log error responses for debugging:

```typescript
if (!response.ok) {
  console.error('API Error', {
    status: response.status,
    error: await response.json(),
    requestId: response.headers.get('X-Request-Id'),
  });
}
```

### Use Request IDs

Include the `X-Request-Id` header from the response when contacting support. It helps us trace the exact request in our logs.
